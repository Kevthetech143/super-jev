# Changelog

## Unreleased
- Fixture, sample and evidence-source folders never rank as answers. A made-up sample about another company (`docs/evidence/<run>/sources/Engineering/Deployment/releases.md`) came back as the answer to "What decision was made about releasing Super Jev v1.0.22?". `is_test_material` now also matches `fixture(s)/`, `__fixtures__/`, `__mocks__/`, `testdata/`, `test-data/`, `test_data/`, `sample-data/`, `sample_data/` and any `sources/` folder under an `evidence/` folder, and routing (step 3) now drops test material the same way it drops bench datasets; connect and word search already skipped it. Takes effect on the next ask; a pointer that already holds such files keeps them connected but they never rank.
- "None of these" check: after the content check, one Jev choice call over the top 4 kept files (each file's 3500-character passage sharing the most question words) asks which file states the answer, with a "none" option ("when torn, pick none"). When "none" wins, each possible-tier file (under 0.85) that Jev saw is dropped; a confirmed file, or one past the top 4, is never dropped. A failed or errored call changes nothing. +1 Jev call on asks with a kept file. `SUPERJEV_NONE_CHOICE=0` turns it off. The trace stage is `none_choice`.
- A file the cover gate demotes is dropped, not kept as "possible". Capping it at 0.84 still returned history-recall/SKILL.md as a possible hit for a made-up question about Kelvin's CLOV verdict; a file that holds almost none of the question's words (coverage under 0.2) is now dropped, and the route-keep and big-file keeps skip it too, so the answer is "not found".
- Word matching is Unicode- and accent-aware. The word pattern matched only plain a-z, so accented words were cut up ("papá" -> "pap", "¿Cuántas" -> "cu" + "ntas", "niño" -> "ni" + "o") and short pieces were dropped, which weakened word search ranking, the cover gate's coverage and the routing prefilter for every non-English user. All of them now share one tokenizer (`words()`/`fold()` in ask.py): Unicode letters and digits, case- and accent-folded, so "papa" and "papá" match. ASCII text tokenizes exactly as before. Common Spanish question words are stopwords like their English ones. Saved pointer words (`pointer-words.json`) carry a tokenizer version and rebuild on their own at the next ask; no other stored index uses the tokenizer.
- A file no longer reaches the confirmed tier while holding almost none of the question's words. A one-passage file is judged as that passage against "none", so a short, on-topic-looking file could pass the 0.85 content check for an event it never names: a made-up question about Kelvin's CLOV verdict confirmed history-recall/SKILL.md, which holds only "kelvin" and "last". After the content check and listwise promote, a confirmed file whose idf-weighted coverage of the question's words (the same weights word search uses) is under `CONFIRM_MIN_COVER` 0.2 is capped at 0.84: possible at most, and dropped on value questions, which have no possible tier. A file word search never indexed gets no opinion. The trace stage is `cover_gate`.
- prepare_bulk now drops cache entries outside the current scope on every run (an old `--root`, a narrowed `--exclude`/`--name`). Before, a refresh only dropped entries whose file was gone from disk, so after a pointer moved from a /tmp stage to `~/.claude/skills` the still-existing /tmp entries stayed in `prepare-cache/<pointer>.json`, and word search, which reads that cache as the pointer's file list, kept returning files that were no longer connected. `allowTargets` is now recorded as full paths, so a relative `--allow-target` replays the same folder from any working directory.
- Connecting `~/.claude/skills` in place crashed with `KeyError` part-way through (parts 1-2 registered, 3-6 left on the old copy): a skill whose SKILL.md is a symlink came back from the connect preview under its target's real path, and prepare_bulk looked its hash up by the path it sent. It now matches preview paths on realpath, as ask.py and auto_heal already do. `--name` now matches case-insensitively (`--name SKILL.md` also takes `skill.md`, the name most fleet skills use). A `--refresh` given a new `--root` no longer inherits the old root's `--no-recurse`, which silently skipped every nested file under the new root. A symlinked file is now judged on its target too: the target must sit under a `--root` or a `--allow-target DIR` folder (repeatable, recorded and replayed on refresh) and pass the same name, folder (profile/, documents/, hidden) and secret-name checks, so a link can no longer pull in logins.md or a profile/ file.
- Connecting a skills folder no longer needs a flattened copy: routing (step 3) sees only each file's name and description, and every skill's entry file is named SKILL.md, so a pointer of skills showed Jev 50 leaves all called "SKILL.md", and a recursive connect of the folder took in every reference doc (920 files against the 250 cap). The workaround was to copy the files into a temp folder as `<skill>__SKILL.md`, which is wiped on reboot and stales the pointer. Now a flat catalog leaf whose file name is shared with another source in the same connect is labelled with its parent folder too (`ebay-return-label/SKILL.md`); unique names are unchanged. `prepare_bulk.py --name GLOB` (repeatable, e.g. `--name SKILL.md`) keeps only matching file names, and is recorded in the recipe so `--refresh` and `refresh_changed.py` replay it. Takes effect on the next connect or refresh of a pointer.
- "Which skill/tool/command ..." asks: the answer is a SKILL.md in the trusted skill roots, which are not connected files, so these asks returned the connected doc about skill search as "possible" for unrelated skills. ask.py now also runs the skills connector (`dispatch.py skills`, one Jev call, in parallel with routing) for such questions and prints its picks first as `skill  <SKILL.md>  [skills: <name>]`. Every principal gets this with no connect step. `SUPERJEV_SKILLS=0` turns it off. The trace stage is `skills`.
- A stale pointer nothing can refresh (no prepare_bulk report, no connect recipe, or a replay that failed) prints its error once per day per principal instead of on every answer, and the other sightings log `stale-quiet` to lookups.jsonl. A pointer that is healing still shows every time. The refresh hint only prints a prepare_bulk command for a pointer prepare_bulk built.
- Stale connector pointers self-heal: a pointer connected through the path connector (memory `connect`, connect_checked, connect_github) rather than prepare_bulk had no recorded recipe, so when one of its files changed auto-heal skipped it as "no-report" on every ask and the hint printed a prepare_bulk command that cannot rebuild it (prepare_bulk reads only .md files). Connect now records its own request (paths, descriptions, structure, principals) as `recipe` in the dataset registry; a new memory action `recipe` reads it even while the pointer is stale (principal-checked; a path-connected dataset from before this change gets one rebuilt from its prepared manifest). A stale pointer with no prepare_bulk report is reconnected inline from that recipe at its files' current bytes (local only, no writer or Jev call, the connector's secret scan still runs; per-pointer cooldown after a success) and read in the same lookup. A dataset built by hand (neither recipe nor path connection) is reported as needing one reconnect through the connector instead of a prepare_bulk command that fails.
- Saving uses ask()'s own evidence: `--answer`, `--approve` (top, `--rank`, `--file`), `--confirm-pick` and the pick-trail flush used to fetch their evidence ticket through memory `search`, a second, weaker ranking (file descriptions only, top 3, no word search or listwise). A file ask() ranked #1 could fail to save with "search returned no-match" (businessfi GEICO pending-asks note). They now cite the file ask() ranked (or the lead picked) directly: a new memory `open` action records an attempt with no retrieval (needs `allowAgentAssist`, like `assist`), `assist` cites the file's opening line plus its line that best matches the answer, and the claim check runs on exactly that cited passage. Kept: the check gate (only CLEAN at >= 0.80 saves), the confident TIME_SENSITIVE refusal, the secret hold and the stale-file check; a question already saved under any pointer (a manual `--add` too) is reported as already cached, never overwritten. `search` stays only as the fallback when no file is known (`--approve` with an explicit pointer) or on an older runtime without `open`.
- Pick trail: a refused pick (TIME_SENSITIVE/REJECT/CONTRADICTED/stale/secret-held) used to be dropped from `pending_picks.jsonl` with only a transient print during the automatic every-5-picks flush, so it vanished from `--pending-picks` with no lasting trace beyond `lookups.jsonl` -- a correct, "fair" refusal looked identical to a silent bug. It now stays in the file tagged `"dropped": <reason>` and lists under a "Dropped (not saved)" section in `--pending-picks`, cleared only by an explicit `--confirm-pick` or `--drop-pick` (being shown does not clear it). (businessfi hand test, 2026-09-25)
- Auto-cache time-sensitive override now requires a confident call: `ask.py --answer`'s gate re-check turned a CLEAN verdict into TIME_SENSITIVE off the raw label alone, ignoring the confidence riding next to it, so a near coin-flip call (label TIME_SENSITIVE at 0.05-0.10 confidence -- jev's own 0.80 "read the source, act on neither answer" line not cleared) was blocking a fully-supported, correct answer. The override now only fires when that label's own confidence is >= 0.80, matching the floor jev uses everywhere else for a call worth acting on. (health-fitness hand test 7)
- Listwise reorder hub exemption (h22, 2026-09-25 fair head-to-head): a hub/copy/write-up file (README/INDEX/PROFILE/`_staging`/pr-history) that wins the listwise call no longer moves back above a non-hub file already ranked ahead of it. `prefer_sources` already demotes a hub below a confirmed or higher-scored note in its folder; the listwise reorder had no matching exemption (unlike the near-twin tiebreak, which already sits hubs out), so it could win the pool and un-demote the hub straight back to #1. Repro: esteban/medical/README.md (0.98, on-topic index) outranked the confirmed 2026-04-09-panel.md (0.91) because listwise picked the README. Documented, not fixed: two held-out recall misses (h16, h17) where the gold ops-report file was never routed as a candidate by any pointer -- both files are indexed and reviewed; the miss is Jev's own routing judgment on a thin, generic description, not a code bug, so no code fix was made (see superjev-ask-path.md's routing section).
- Listwise reorder + promote: after content check, one extra Jev call runs over every file that reached the possible tier (>= 0.60), asking which single one best answers the question. The winner moves to #1 of the final ranking, never demoting anything else, and is promoted to confirmed (>= 0.85) only if its own winning probability is itself >= 0.9. A failed, timed-out, or "none of these" call leaves today's order and scores unchanged (fail open). `SUPERJEV_LISTWISE=0` turns it off. Tested against the installed baseline and a separate AND-gate variant on the same question set (`superjev-tests/listwise-2026-09-25/result.md`, "Version C"): Improved on internal eval (details kept private). Cost: +1 Jev call on the ~80% of asks where a file reaches the possible tier at all. Two runs per version against a comparable noise floor -- a real gain, not a clean settled one; see the result.md verdict.
- Batched Jev calls: routing for every pointer runs in one navigation-cli process whose Jev questions share calls (new `navigate-many` memory action), and every file's content check rides one run the same way. Each question is still answered on its own, so labels and scores mean the same; a batch over the input budget is split automatically, and an over-ceiling reply splits it again. `SUPERJEV_BATCH_JEV=0` goes back to one call per pointer/file. Full eval, same-day data, live (no caches): Jev calls per ask 25.0 -> 3.8, seconds per ask 10.0 -> 5.8. Improved on internal eval (details kept private).
- Claim check size guard counts estimated tokens instead of characters: number-dense evidence under the old 110,000-character cap could still overrun Jev's ceiling and fail. Evidence too big for one call is now split into parts, each checked on its own and merged (a contradiction or red draft-level label anywhere wins; otherwise a claim any part supports is SUPPORTED).
- Word search scores each file by its best 3500-character passage instead of the whole file, so a long note (the 36 KB medical timeline) is no longer sunk by its unrelated visits; a written phone number (212-305-6390) counts as the words "phone" and "number"; a file under 0.55x the best not-yet-routed word score takes no read slot. Improved on internal eval (details kept private). Fixes "NYP ENT phone number" (hand test 6).
- Stale pointers: when every file of a stale pointer is already reviewed at its current bytes (auto-heal used to skip it as "no-change" forever, e.g. primary-reference), the ask reconnects it inline with `--no-findability` (no writer or Jev calls; one 45 s budget for all reconnects in a lookup, then left running in the background; no cooldown after a failed or timed-out reconnect) and reads it in the same lookup. Split parts (`<pointer>-N`) now heal through the parent's report instead of skipping as "no-report". Real changes keep the background refresh.
- Content check, spread answers: among files in the same tier, a file read as several passages ranks on its best passage plus half the on-topic probability the other passages took (`file_score`, SPREAD_CREDIT 0.5), so a note whose answer spans passages outranks a sibling with one slightly stronger passage. Tiers still come from the best single passage (possible >= 0.60, confirmed >= 0.85; blend capped at 0.84); live-value asks get no blend. No extra Jev calls.
- Routing cost: a pointer is not routed when a question of 2+ words has none of them (or a listed synonym: doctor/physician, dad/father, car/vehicle...) in any of its files. Never skipped: a pointer holding a resolved person's folder, or one whose files cannot be listed. Words are read locally via `sources` beside routing, once per pointer generation (`$STATE/pointer-words.json`); word search still searches every pointer. Trace stage `prefilter` lists skipped pointers.
- Full eval on top of #161 (corrected key): Improved on internal eval (details kept private). Jev calls per ask 28.9 -> 26.0 (routing 21.3 -> 18.4).
- Source over copy: a README/INDEX/PROFILE hub yields to a note under its own folder that is confirmed or scored higher than the hub, a `_staging/` or `_TEMPLATE` copy yields to any note that passed the content check (both then list as possible), and a PR-history write-up yields to a confirmed doc. With nothing to yield to they keep their place (clov/README stays the dashboard). No extra Jev calls.
- Person resolution: "my dad"/"my mom"/a person's name/"I, me, my" resolves to `~/agents/global/documents/<name>/` folders ("my wife and I" = both; group words like parents/kids/family/our, or a relation no folder claims, filter nothing) (relation read from that folder's PROFILE `Relation:` line); other people's files are not read, not confirmed, and pointers holding only their files are not asked. No name resolved, nothing filtered.

- Pick trail: `--used last --rank N --answer "..."` logs which listed file an agent used; every 5 picks the claim checker auto-saves CLEAN ones as `agent-pick+check`, unsure ones wait in `--pending-picks`. (#155)
- `--approve --rank N` / `--file PATH` saves evidence only from the picked file (matched by full path); a same-name file in the same tree (clov/analysis/README.md vs clov/README.md) can no longer supply the quote. If the search has no passage from the picked file, approve cites the file's own reviewed lines that best match the answer (assisted review, needs `allowAgentAssist`); the pick trail uses the same evidence path. The saved quote is the picked file's passage that best matches the answer, not its first section.

A refresh that names only some of a pointer's registered principals now reconnects with all of them instead of failing with scope-change and leaving the pointer STALE.
